# StructuralAI — AI-Powered Structural Health Monitoring System

StructuralAI is a full-stack platform for automated crack detection, structural health
scoring, and physics-based damage assessment of concrete/masonry structures from photographs
and structural parameters. It combines computer vision (crack detection, segmentation, and
width/depth measurement), classical machine learning (structural health index, risk, and
remaining-useful-life prediction), and original physics-based engineering models (fracture
mechanics capacity analysis and closed-loop epoxy grouting control).

## Architecture overview

```
Image upload ──► Crack detector (SwinCrackNet / CrackNet) ──► bounding boxes
             └─► U-Net segmentation ──► crack mask ──► skeletonization ──► width/depth (IS 456)
                                                                        └─► physics fracture engine (LEFM)
                                                                        └─► grouting controller (epoxy injection plan)

Structural parameters ──► XGBoost / RandomForest models ──► SHI, Risk class, RUL
                                                          └─► SHAP explainability
                                                          └─► Gemini-based narrative report + PDF
```

Two frontends talk to the same FastAPI backend: a React SPA (primary) and a legacy Streamlit
dashboard (`app.py`).

## Tech stack

- **Backend:** FastAPI, Uvicorn
- **Computer vision / deep learning:** PyTorch, Torchvision (Swin Transformer backbone), OpenCV, Albumentations
- **Classical ML:** scikit-learn, XGBoost
- **Explainability:** SHAP
- **LLM / agent:** LangChain + Google Gemini (`gemini-1.5-flash`)
- **Reporting:** ReportLab (PDF generation)
- **Frontend:** React, Axios, Recharts
- **Legacy dashboard:** Streamlit

## Datasets

The repo ships pre-populated `data/` folders built from the following public research
datasets. If you need to re-download or refresh them, sources are below. **All third-party
datasets below are for non-commercial research use only** — check each license before any
commercial deployment or patent claim that relies on them (see [License and dataset
attribution](#license-and-dataset-attribution)).

| Dataset | Used for | Location in repo | Source |
|---|---|---|---|
| **Concrete Crack Images for Classification** (Özgenel & Sorguç) — 20,000 positive + 20,000 negative 227×227 patches | Training `CrackNet` / `SwinCrackNet` binary classifiers | `data/crack_detection/Positive`, `data/crack_detection/Negative` | [Mendeley Data](https://data.mendeley.com/datasets/5y9wdsg2zt/2) · mirrored on [Kaggle: Surface Crack Detection](https://www.kaggle.com/datasets/arunrk7/surface-crack-detection) |
| **SDNET2018** (Utah State University) — 56,000+ labeled images of cracked/uncracked decks (D), pavements (P), and walls (W) | Supplementary classifier training data | `data/crack_detection/sdnet2018/{D,P,W}/{C*,U*}` | [Utah State University Digital Commons](https://digitalcommons.usu.edu/all_datasets/48/) |
| **DeepCrack** (Wuhan University, Liu et al. 2019) — pixel-level crack segmentation masks | Training `TinyUNet` segmentation model; converted to YOLO boxes | `data/segmentation/deepcrack/` | [GitHub: yhlleo/DeepCrack](https://github.com/yhlleo/DeepCrack) |
| **CrackForest Dataset** (Shi et al., IEEE T-ITS 2016) — annotated road crack images | Segmentation ground truth / benchmarking | `data/segmentation/` (`image/`, `groundTruth/`, `seg/`) | [GitHub: cuilimeng/CrackForest-dataset](https://github.com/cuilimeng/CrackForest-dataset) |
| **YOLO-format crack detection set** — converted from DeepCrack masks via `scripts/prepare_yolo_dataset.py` | Legacy YOLOv8 detector (superseded by CrackNet/SwinCrackNet) | `data/yolo_dataset/`, `data/yolo_dataset_tiny/` | Derived in-repo, see `dataset.yaml` |
| **Synthetic structural tabular dataset** — 350 rows, generated by `scripts/generate_tabular_data.py` from formula + Gaussian noise | Training SHI regressor, risk classifier, RUL regressor | `data/tabular/structural_data.csv` | Generated, not downloaded — regenerate with `python scripts/generate_tabular_data.py` |

`data/knowledge_base/` is currently an empty placeholder (not wired into any code path yet).

## Project structure

```
backend/main.py          FastAPI app — all REST endpoints
app.py                   Legacy Streamlit dashboard (same backend)
main.py                  Uvicorn entrypoint (runs backend.main:app)
scripts/
  cracknet.py             CrackNet CNN architecture
  swin_cracknet.py         SwinCrackNet (Swin-Tiny + custom head)
  detect_cracknet.py       Sliding-window + NMS detector wrapper (CrackNet)
  detect_swin_cracknet.py  Sliding-window + NMS detector wrapper (SwinCrackNet)
  train_cracknet.py        Trains CrackNet
  train_swin_cracknet.py   Trains SwinCrackNet (2-phase fine-tuning)
  train_unet.py            Trains TinyUNet segmentation model
  train_ml.py              Trains SHI / risk / RUL tabular models
  train.py / detect.py / predict.py   Legacy YOLOv8 pipeline
  crack_width_measure.py   Skeleton + distance-transform crack width measurement
  physics_fracture_engine.py   LEFM fracture mechanics + residual capacity engine
  grouting_controller.py   Closed-loop epoxy injection controller
  agent.py                 LangChain/Gemini structural inspection agent
  explain.py                SHAP explainability plots
  extract_features.py       Crack feature extraction from masks
  generate_report.py        PDF report builder
  generate_tabular_data.py  Synthetic tabular dataset generator
  prepare_yolo_dataset.py   DeepCrack masks → YOLO label converter
models/                  Trained weights (cracknet, swin_cracknet, unet, ml, yolo)
data/                    Datasets (see table above)
frontend-react/          React SPA
reports/                 Generated PDF reports / sample outputs
outputs/                 SHAP plots, benchmark results
```

## Setup

### Prerequisites

- Python 3.11+ (tested on 3.11 and 3.12)
- Node.js 18+ and npm (tested on Node 22)
- A Google Gemini API key (for the AI narrative report and chat features — optional; the
  agent falls back to a rule-based report if absent)

### Backend

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
pip install langchain-google-genai
```

> `requirements.txt` currently lists `langchain-openai`/`openai`, but the code actually uses
> Google Gemini via `langchain-google-genai` — install it separately until `requirements.txt`
> is updated.

Create a `.env` file in the project root:

```
GEMINI_API_KEY=your_google_gemini_api_key_here
```

### Frontend

```bash
cd frontend-react
npm install
```

Create `frontend-react/.env` if you need to override defaults (default backend URL is
`http://localhost:8000`, see `src/services/api.js`).

## Running the app

**Backend (FastAPI):**

```bash
python main.py
```

or

```bash
uvicorn backend.main:app --reload --port 8000
```

**Frontend (React):**

```bash
cd frontend-react
npm start
```

Then open `http://localhost:3000`.

**Legacy Streamlit dashboard** (optional, talks to the same backend):

```bash
streamlit run app.py
```

## Training the models

All training scripts read from `data/` and write weights to `models/`.

```bash
python scripts/train_cracknet.py        # CrackNet CNN classifier
python scripts/train_swin_cracknet.py   # SwinCrackNet transformer classifier
python scripts/train_unet.py            # TinyUNet segmentation
python scripts/train_ml.py              # SHI / risk / RUL tabular models
python scripts/generate_tabular_data.py # regenerate synthetic tabular dataset
```

The legacy YOLOv8 pipeline (superseded by CrackNet/SwinCrackNet, no longer called from the
backend) can still be trained with `python scripts/train.py`.

## Known issues

- `scripts/acoustic_optical_inversion.py` — imported by `backend/main.py` for the
  `/api/unified_invention_pipeline` endpoint — is missing from the working tree (only a
  compiled `.pyc` remains). That endpoint will raise an `ImportError` until the source file is
  recovered or rewritten.
- The `/api/unified_invention_pipeline` and `/api/pump/simulate_step` endpoints are not yet
  wired into the React UI (API-only).
- `TinyUNet` is defined independently in three places (`backend/main.py`,
  `scripts/train_unet.py`, `scripts/extract_features.py`) rather than a shared module.
